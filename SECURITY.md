# Security and privacy concerns

This support repository covers **FixtureFill**, published by **Kynastro**. This documentation covers **0.1.2**. Include the affected version in a report; this document does not promise response or remediation deadlines.

## Report privately

Do not disclose a vulnerability, exploit details or sensitive information in a public issue or screenshot.

If this repository's **Security → Advisories** page offers **Report a vulnerability**, use that private reporting channel. Its availability depends on the repository's private vulnerability reporting setting; this document alone does not enable it.

If the private reporting option is unavailable, use a verified private Kynastro support contact shown on the official extension listing. If neither channel is available, withhold technical details until a private channel is available. Do not guess an email address or send sensitive information to an unverified contact.

## Information to include

- Affected FixtureFill, browser and operating-system versions.
- A concise description of the security or privacy impact.
- Reproduction steps using a local or disposable test page and synthetic data.
- Whether the problem requires a particular mode, field type or framework.
- Redacted evidence only when needed to explain the issue.

Do not include credentials, tokens, passwords, private URLs, personal information or confidential production data, even in the initial private report. Do not attach a complete browser profile or production page dump.

If a secret was accidentally posted publicly, revoke or rotate it through the relevant service and remove the public content where possible. Deletion does not guarantee that copies no longer exist. Continue the report through a private channel.

For ordinary non-sensitive bugs and compatibility reports, use the public issue forms described in [Support](SUPPORT.md).
